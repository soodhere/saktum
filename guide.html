Saktum Check, step by step

Test MCP servers, build ones that earn top grades, run it in CI, prove trust to others, and govern what agents do. Free and open source (Apache-2.0).

Start in 60 seconds

Needs Node.js 20 or later (Windows, macOS or Linux). Nothing is uploaded: Saktum runs on your machine or in your CI.

npx saktum demo

A grocery agent and a travel agent following real instructions (rules, preferences, substitutions, upsells, fees), every decision explained and signed, in 60 seconds. Then:

npx saktum

Shows the four main journeys. Then test a real server:

npx saktum check -- npx -y @modelcontextprotocol/server-memory

You get a trust grade, an agent-readiness grade, a trust card (what was tested and what was not), findings with fixes, and a signed result in saktum-report.json.

1. Test an MCP server

Grade a local server (passive: no tool is called)
npx saktum check -- npx -y some-mcp-server
Grade a remote server, including OAuth sign-in
npx saktum check https://your-server.example/mcp
Also call read-only tools and measure load (only servers you own)
npx saktum check --active -- node build/index.js
Run your own test cases (saktum.tests.yaml)
npx saktum test -- node build/index.js
Every check, and the standard behind it
npx saktum checks
Why a server will not start
npx saktum doctor -- npx -y some-mcp-server

2. Build a server that earns top grades

Start a new server (TypeScript or Python)
npx saktum init my-server --lang ts
Static checks on tool definitions in your code
npx saktum lint
Missing annotations, as code to paste (--format py for Python)
npx saktum fix -- node build/index.js
Save a real call as a test case
npx saktum call get_order --args "{\"id\":\"1\"}" --save-test order-1 -- node build/index.js
Re-check on every save
npx saktum check --watch -- node build/index.js
Lock your tools, then catch breaking or silent changes
npx saktum snapshot -- node build/index.js
npx saktum diff saktum.lock.json -- node build/index.js
README tools table and client set-up
npx saktum docs -- npx -y your-package

Templates from init earn trust A and agent readiness A out of the box, with test cases, CI and an AGENTS.md for coding agents.

3. Let your coding agent do it

Saktum is itself an MCP server: your agent can test, fix, diff and document MCP servers.

Claude Code
claude mcp add saktum -- npx -y saktum mcp
Claude Desktop, Cursor or VS Code (MCP configuration)
{ "mcpServers": { "saktum": { "command": "npx", "args": ["-y", "saktum", "mcp"] } } }

Then ask: "Check the MCP server started by node build/index.js and fix anything below A." One-click buttons for Cursor and VS Code are on the home page.

4. Run it in CI

Fail pull requests on new problems, and see findings in GitHub code scanning.

# .github/workflows/saktum.yml
name: saktum
on: [push, pull_request]
permissions:
  contents: read
  security-events: write
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: soodhere/saktum-check@v0.8.1
        with:
          target: "-- node build/index.js"
          args: "--active --tests saktum.tests.yaml"   # --active only for your own server
          sarif: "true"
          fail-on: high
          # baseline: saktum-baseline.json          # optional: fail only on new findings
          # policy: saktum-policy.yaml               # optional: your organisation's rules

5. Prove trust to others

A signed attestation and README badge
npx saktum attest saktum-report.json
Publish it to the public trust ledger (opens a pre-filled issue)
npx saktum attest saktum-report.json --publish
Verify the ledger, or look a server up
npx saktum ledger verify
npx saktum ledger find my-server
A security packet for a customer's review (print to PDF)
npx saktum packet saktum-report.json

The trust ledger is append-only and hash-chained: anyone can verify every signature and the whole chain.

Passports: trust you can see

A one-page visual card for a server (identity, every tool and its effect, grades, maturity, how to verify) or for an agent (its mandate and the path of its calls).

npx saktum passport -- npx -y @modelcontextprotocol/server-memory
npx saktum passport --agent agent-mandate.json --receipts receipts.jsonl

Servers recorded in the trust ledger get a public passport page in the passport gallery. For organisations, npx saktum assess --fleet inventory.json --org "Acme" produces an executive MCP Trust Assessment.

6. Govern what agents do (preview)

Give an agent its own identity and a mandate you sign; Saktum blocks what the mandate does not allow and writes a signed, chained receipt for every tool call.

Agent identity and mandate
npx saktum agent create --name "Shopper" --autonomy act --max pay_for_order.amount=50 --approve-above amount=25 --allow-value pay_for_order.currency=CAD --operator "Demo Grocer"
Use in place of the server command in your agent's configuration
npx saktum proxy --mandate agent-mandate.json --enforce -- npx -y @modelcontextprotocol/server-memory
The path, not the answer: tools, order, retry storms, denials
npx saktum receipts summary
Prove the receipts were not altered
npx saktum receipts verify

Write instructions as JSON (--intent examples/mandate-grocery.json; guide: docs/MANDATES.md). See how Saktum reads a server’s tools: npx saktum bindings -- <server>.

Preview limits: local (stdio) servers; receipts are signed by the agent side until the Saktum gateway co-signs them.

Fits your tools, and pays for itself

Saktum’s evidence in the standards your tools already accept, plus the business case.

Monitor approved servers; alert on changed tools or grade drops
npx saktum watch saktum-allowlist.json --webhook https://your-webhook
Agent receipts as OpenTelemetry traces (file, or straight to a collector)
npx saktum receipts export --otel receipts.otlp.json --endpoint http://localhost:4318
Attestation as a W3C Verifiable Credential, and verify one
npx saktum attest saktum-report.json --vc
npx saktum vc verify saktum-attestation.vc.jwt
What tool definitions cost a year, and the savings
npx saktum roi --tokens-per-turn 32833 --agents 10 --vendor-reviews 20

Daily monitoring as a GitHub workflow: copy examples/saktum-watch.yml. The executive assessment (saktum assess) includes the business case.

Evidence for governance

Saktum’s evidence mapped to the EU AI Act, NIST AI RMF, ISO/IEC 42001, the OWASP LLM Top 10, DORA and NIS2, and GDPR and the DPDP Act. It supports evidence; it never claims compliance.

npx saktum evidence --framework all
npx saktum evidence --framework eu-ai-act --markdown

Coding agents: npx saktum demo --story coding keeps an agent to its own repository and makes production releases wait for your signed approval.

7. For organisations

Every MCP server on this machine: cost, duplicates, risks
npx saktum scan-config
Check servers against your organisation's policy
npx saktum scan-config --policy saktum-policy.yaml
An allowlist for your MCP firewall or gateway
npx saktum allowlist reports/*.json
Organisation-wide inventory from many machines
npx saktum scan-config --yes --out setup.json
npx saktum fleet setups/*.json --policy saktum-policy.yaml --html inventory.html

Data handling, air-gapped use and the MCP Trust Pilot: enterprise guide · discuss a pilot.

Safety, in short

  • Passive by default: Saktum connects as any MCP client would and never calls tools unless you add --active, which is only for servers you own.
  • Your secrets stay yours: your environment is never passed to servers under test; configured secrets are never printed; command lines in reports are redacted.
  • Signed results: every result and attestation can be checked with npx saktum verify; self-tested results are labelled L1.
  • Windows: in PowerShell, put JSON arguments in double quotes with escaped inner quotes, as in the examples, and quote paths that contain spaces.
