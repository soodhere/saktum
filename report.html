What we found

Agent readiness

47.6% of servers declare no danger annotations and 7.8% declare them on only some tools. 40.8% earn agent readiness A. Tool definitions cost a median of 3,337 tokens per agent turn (90th percentile 34,804), and 15 servers exceed 20,000 tokens before an agent does any work.

Five fixes for maintainers

  1. Declare danger annotations (readOnlyHint, destructiveHint) on every tool, so clients can ask before an agent deletes something.
  2. Trim tool definitions: every token is paid on every agent turn. Shorten descriptions and drop rarely used tools.
  3. Publish with npm provenance (npm publish --provenance from CI) and avoid install scripts.
  4. Answer unknown tools with an error, never success, and keep errors free of stack traces and file paths.
  5. Test what your tools return: declare an outputSchema and run your own test cases in CI (npx saktum test).

Method, ethics and limits

Supply-chain signals come from public npm registry metadata. The deep assessment installed each server with install scripts disabled and ran Saktum Check Saktum Check 0.2 in passive mode on a disposable machine: no tool was called, no credentials were supplied, and nothing was sent to any third-party service. Servers that need configuration to start (94 of 200) or that list no tools without credentials (3) are not graded. This report names no server; individual results are shared only with maintainers on request. Results describe each package at the time of the census and are not a guarantee of security. Capability inference is deliberately conservative and may miss capabilities rather than invent them.
